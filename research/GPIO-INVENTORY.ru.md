# Перечень GPIO и границы поиска управления вентиляторами

17 октября 2026 года. **Предыдущая проверка не охватывала все пути GPIO.**
Она включала 23 прямые ссылки на основной обработчик записи GPIO SoC и
связанный код PoE/охлаждения. Теперь проверены обработчики чтения и направления,
прямые записи в регистры, штатная конфигурация платы, драйвер внешних GPIO и
один прослеженный путь косвенных вызовов. Дополнительной команды скорости
вентиляторов в этих путях не найдено. Это всё ещё не доказательство разбора
всех возможных вычисляемых переходов в прошивке.

Источник: штатный BIN июня 2023 года, SHA-256
`c9ab17eda7af714f00692d41f440ce84ed0d6c7d678634c364ec1154bb7e3f32`.
Обращений к устройству и изменений прошивки не было.
[Воспроизводимые результаты](gpio-inventory-evidence.json) ·
[Предыдущая проверка охлаждения](COOLING-PATHS.ru.md).

## Все 32 бита из предоставленного состояния

Владелец ранее прислал `cnr=0xc2e7ff00`, `dir=0x39000000`,
`data=0x39780000`. Это номера битов регистров, а не контактов разъёма.
Здесь «GPIO» означает сброшенный бит CNR, согласно работе штатного обработчика.
«Другая функция» означает установленный бит CNR; конкретная функция из одного
этого бита не определяется. При другой функции бит направления не доказывает
направление сигнала. Это прежнее наблюдение, а не новое измерение.

| Бит GPIO | Выбор в снимке | Найденная связь в коде |
| --- | --- | --- |
| 0–7 | Вход GPIO | В рассмотренных путях вызов с фиксированным номером не найден |
| 8–18 | Другая функция | Общий обработчик настраиваемых входов допускает 8–31; в штатной конфигурации отключён |
| 19 | Вход GPIO | Выбор copper/fiber для внутреннего порта 25 |
| 20 | Вход GPIO | Выбор copper/fiber для внутреннего порта 24 |
| 21 | Другая функция | Чтение используется обработчиком кнопки/сброса конфигурации |
| 22 | Другая функция | Путь reset/watchdog позднее выбирает выход GPIO и записывает 0 |
| 23 | Другая функция | Вызов с фиксированным номером не найден |
| 24 | Выход GPIO | Устанавливается в 1 при старте; импульс 0/1 при инициализации PoE |
| 25 | Другая функция | Необязательный вход режима платы: `25 + configured_offset`; по умолчанию отключён |
| 26 | Вход GPIO | Выбирает режимы двух индикаторов; в выборе выхода по нагрузке PoE не участвует |
| 27 | Выход GPIO | Двоичный выход с гистерезисом по нагрузке PoE; v0.1.2 позволяет временно изменить его |
| 28 | Выход GPIO | Тактовая линия программной шины устройств PoE |
| 29 | Выход GPIO | Линия данных этой шины; при обмене направление меняется |
| 30–31 | Другая функция | Вызов с фиксированным номером не найден |

«Вызов с фиксированным номером не найден» не означает свободный или безопасный
для использования контакт. Общие обработчики принимают номер динамически.
Направление в одном снимке также не описывает все моменты обмена по шине или
последующего сброса.

## Дополнительные прямые обращения к регистрам

`0xbfc101c0` (файл `0x81c0..0x8270`) напрямую сбрасывает биты 19 и 20 в
`0xb8003500` и `0xb8003508`. Оба становятся входами GPIO; записи в регистр
данных GPIO нет. Три запуска с разными начальными словами подтвердили
сохранение остальных битов GPIO и слова данных. Записи в регистры коммутатора
также выполнялись на синтетической MMIO-памяти; вызовы в этих случаях не
подменялись. Предыдущий аудит охлаждения явно подменял эту функцию и не
устанавливал её содержимое.

`0xbfc29254` читает GPIO20 для индекса 0 и GPIO19 для индекса 1. Ветви используют
штатные строки `set port %d to fiber mode` и `set port %d to copper mode`.
Значение PHY `0xc984` из лога владельца выбирает ID платы `0x43` в `0xbfc2eba8`.
Выполнение штатного опроса `0xbfc293c8` с этим ID и присланным словом данных
даёт **copper для внутренних портов 24/25 и fiber для 26/27**, как в логе
загрузки. Функции изменения режима портов подменены: проверено решение CPU,
а не физические соединения. Внутренние ID — не номера портов передней панели.

Обработчик GPIO21 в `0xbfc51080` считает низкие уровни. На пятом таком отсчёте
он вызывает `0xbfc51f48`, определяемую по штатной диагностической строке
`sal_flash_cfg_reset`, затем обработчик сброса системы. Это не счётчик
тахометра вентилятора. Выход GPIO22 находится в отдельной функции reset/watchdog.

## Внешние GPIO и косвенный вызов, пропущенный поиском прямых ссылок

В BIN есть имена `dal_maple_rtl8231_init`,
`dal_maple_extGpio_pin_data_set` и соответствующих функций чтения/направления.
Они определяют программный драйвер, но не подтверждают, какая физическая
микросхема установлена на этой плате.

Для ID платы `0x43` функция `0xbfc29550` включает внешнее устройство 0 и по
таблице RAM `0xbf0008f0` настраивает следующие входы:

| Внутренний порт | Пара входов внешнего GPIO |
| --- | --- |
| 24 | 8, 9 |
| 25 | 3, 4 |
| 26 | 24, 25 |
| 27 | 13, 14 |

Выполнены штатные функции включения/направления с подменой низкоуровневого
обмена регистрами: 38 операций чтения/записи, записи в регистры 0, 2, 3, 4, 5
и 6. Эта инициализация не пишет в регистры выходных данных драйвера. Она не
доказывает, что физическое внешнее устройство подтвердило эти операции.

**У записи внешнего GPIO действительно есть вычисляемая ссылка на функцию.**
По смещению файла `0x20fd4` код собирает адрес `0xbfc24588`, передаёт его в
настройку функций обратного вызова `0xbfc11590` и сохраняет в структуре по
адресу `0xbf016ac8 + 0x14`. Затем функции программной последовательной шины
вызывают его через `jalr`. Поэтому одного отсутствия прямых вызовов было бы
недостаточно: такой поиск пропустил реальный путь записи.

Прослеженный потребитель — обработчик среды/скорости оптических модулей
`0xbfc28da4`: чтение адреса `0x50`, смещений 12 и 11, диагностическая строка
`pOpticalConf[%d].media_speed=%s speed=%s`. Таблица тактовых линий и данных для
портов находится в RAM `0xbf000980`. Нумерация этих внешних GPIO отдельная и
не совпадает с GPIO SoC выше. Опрос для ID платы `0x43` идёт по ветке внутренних
GPIO; эмуляция подтверждает отсутствие вызова этого внешнего обработчика
оптических модулей. Потребитель для вентиляторов в данном пути не выявлен.

## Пути, зависящие от конфигурации

Штатная конфигурация платы в update-файле `0xf7000..0xf764c` загружается из
flash `0xb40ff000`. В сохранённом оригинальном экспорте SPI байты по адресам
`0xff000..0xff64c` совпадают. Выполнение штатного загрузчика конфигурации
подтверждает:

- Настраиваемая функция четырёх входов по смещению `0x1a8` выключена;
  четыре номера контактов содержат служебное значение `0x89`.
- Необязательная функция входа по `0x4e4` выключена; смещение номера по
  `0x4e8` равно 0.
- Все шесть записей общей маскированной инициализации регистров, начиная
  с `0x4fc`, выключены. В общем случае этот путь умеет вычислять адреса
  регистров SoC для записи.

Это штатные/архивные значения, а не чтение RAM текущей работающей прошивки.
Они не позволяют заявить, что путей произвольной записи регистров нет.

## Охват и вывод

Поиск включает 7 прямых ссылок на основной обработчик выбора функции GPIO,
17 — направления, 23 — записи данных и 6 — чтения. Для восьми альтернативных
обработчиков SoC не найдено прямых ссылок, выровненных указателей или
подходящих соседних пар LUI + ADDIU/ORI. Проверены стартовый код, копируемый
в RAM код и указанные интервалы runtime; поиск выровненных указателей по
всему файлу включает таблицы данных. Пары инструкций — синтаксические кандидаты
с возможными ложными совпадениями; установленные применения разобраны выше.

GPIO27 остаётся найденным кандидатом на двоичное управление охлаждением,
GPIO26 — входом индикации. Дополнительная настройка заполнения PWM, целевых
оборотов, отдельного выхода для каждого вентилятора или повторного запуска
при остановке этой проверкой не выявлена. Физическая связь GPIO27 с разъёмами
вентиляторов не подтверждена. Полная распиновка и все возможные вычисляемые
пути **не установлены**.

Воспроизведение после установки `requirements-dev.txt`:

```bash
python3 tools/audit_gpio_inventory.py vendor/tp-link/tl-sg1218mpe-v5/20230616/TL-SG1218MPE-UN-V5-1.0.0-Build-20230616-up.bin > research/gpio-inventory-evidence.json
```

В результат включены все 32 бита снимка, хеши BIN/блоков, ссылки на обработчики,
кандидаты вычисляемых ссылок, явные подмены, поля конфигурации и операции
с внешними регистрами.
