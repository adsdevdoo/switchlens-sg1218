# Материалы анализа

Это история статического исследования, а не журнал стендовых испытаний.
`REPORT.txt` — исходный отчёт; `COMPARISON-AND-POE.txt`,
`HTTP-JSON-FOLLOWUP.txt`, `MIB-LOOPS-FOLLOWUP.txt` и `SYSTEM-INFO.txt`
содержат последующие дополнения. Более поздний вывод заменяет раннее
предположение только при наличии указанного доказательства.

Актуальное дополнение: `PLATFORM-FOLLOWUP.md` уточняет вход SHA-1 в SignCheck,
startup RAM, передачу обновления загрузчику и параметры таймера. Его числовые
данные воспроизводит `tools/audit_platform.py`; результат —
`platform-evidence.json`. `PRIOR-ART.md` содержит найденные внешние проекты,
границы их применимости и ссылки на первоисточники.

В частности, ранняя запись «сравнение версий невозможно без файлов» относится
к моменту первого отчёта. Последующее сравнение описано в COMPARISON-AND-POE.
Доступность старых файлов не означает прохождения проверок подписи загрузчика.

`mib-map.json` — результат ограниченной трассировки веток с имитацией регистров,
не запуск прошивки и не измерение реального ASIC. `metric-sources.json`
сопоставляет поля с найденными источниками и отмечает неизвестное.

Упомянутые в отчётах полные файлы дизассемблирования в Git не включены.
С предоставленным отдельно BIN их можно получить read-only инструментами
`tools/audit.py`, `tools/audit_http.py`, `tools/audit_mib.py` и
`tools/disassemble.py`. Все они проверяют SHA-256 целевой версии.

Пример для System Info и getter описания, из корня проекта:

```bash
python3 tools/disassemble.py /path/image.bin 0x37388 0x376f8
python3 tools/disassemble.py /path/image.bin 0x49e18 0x49e78
```

Смещения включают16байт update header; конец диапазона исключается.
Дизассемблирование байтов само по себе не доказывает назначение функции.
