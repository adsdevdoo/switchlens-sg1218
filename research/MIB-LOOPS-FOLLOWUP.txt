категории; эквивалентность суммы IF-MIB ifInDiscards не доказана.
По той же карте штатный TxBadPkt(selector21) соответствует excessive collisions;
не обещать, что штатный web TxBadPkt покрывает все ошибки передачи.

3. ОБНАРУЖЕННЫЕ ОСОБЕННОСТИ API
Проверено:68селекторов переходят прямо на0xbfc1d9e0 и возвращают0 без чтения/записи
выхода. Нулевой return code не является достаточным признаком поддерживаемой метрики.
Проверено:selector58->file15c30 читает+9c в локальную stack+20, записывает только
high=0 в output и переходит к выходу. Low остаётся прежним. Это наблюдаемая
аномалия данной ветки; причины неизвестны. Нужен отдельный проверенный backend
чтения+9c, либо tx_packets_256_511:null. Нельзя получать его вычитанием двух
неодновременных чтений суммарного и RX счётчиков.
Проверено:10селекторов суммируют два32битных регистра через addu, high=0; перенос
теряется. Для64битных сумм читать составляющие отдельно и суммировать собственным
кодом, но это не гарантирует одновременности и не расширяет аппаратный счётчик.
Проверено:helper BFC1D7F0/file157f0 затирает код возврата BFC10768 нулём.
Следовательно, даже разрешённый selector не гарантирует успешное аппаратное чтение.
Проверено:в исследованных ветках getter нет вызовов функции записи MMIO. Это не
доказательство отсутствия аппаратных побочных эффектов чтения; verify latch/reset.
Проверено по OpenWrt commit2025:для64битного чтения добавлена защита от переполнения
low между чтениями. Штатные selector1/9 такой повторной проверки не имеют.
Гипотеза реализации: high-low-high с ограничением числа повторов, после проверки
аппаратного поведения. До этого не обещать консистентный64битный snapshot.

4. ЗАЩИТА ОТ ПЕТЕЛЬ
Проверено по строкам и аргументам диагностического вывода:
RLDP: current loop mask BF00E280, previous BF00E284; file21f48..21fc8.
RLPP: current loop mask BF00E2A0, current selfLoop BF00E2A4;
previous BF00E2A8/BF00E2AC; file231d0..23298.
Проверено:mask update в2293c..22a18 получает bitmask через BFC28250->BFC1FC18.
Последняя функция начинает с1<<port и может заменить его маской группы из
регистров0x3e00+4*i. Поэтому маска может учитывать LAG, а не только один порт.
Проверено:consumer file47f34..47f48 проверяет bit после логический->физический
mapping; в48050..480c4 есть вызовы изменяющих состояние портов функций.
Проект:из JSON читать globals как raw mask, не вызывать tick/обработчик защиты
ради обновления показаний. Нулевой mask при выключенной функции не означает,
что отсутствие петли проверено. Какой механизм активен и точную семантику
loop/selfLoop/blocked проверять отдельно. Не называть маску уже доказанным
состоянием фактической блокировки каждого порта.

5. ВОСПРОИЗВЕДЕНИЕ
python audit_mib.py firmware.bin [openwrt-dsa.c] > mib-map.json
Скрипт сверяет SHA256 и выполняет ограниченную трассировку веток по инструкциям;
чтения регистров заменены синтетическими значениями. Это не эмуляция ASIC/устройства.
Без reference-файла имена внешней карты не добавляются; сами пути чтения доступны.
Сводка:68 no-op,45 low-word,2 two-word,10 sums,1 incomplete output.
Дизассемблирование: mib-disassembly.txt, loop-disassembly.txt.
