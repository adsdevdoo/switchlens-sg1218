# Отчёт производителю: изменение заводского MAC через TDDP без авторизации

Обновлено 18 октября 2026 года по результатам проверки владельцем на устройстве.
Владелец сообщил, что уже отправил предыдущий отчёт; этот документ содержит
дополнительные доказательства к нему. Ассистент не отправлял это обновление TP-Link.

## Устройство и область проверки

- TP-Link TL-SG1218MPE(UN) V5, штатная база 1.0.0 Build 20230616.
- Проверка на устройстве: по сообщению владельца установлена модифицированная
  **SwitchLens v0.1.4**.
- SHA-256 штатного обновления:
  `c9ab17eda7af714f00692d41f440ce84ed0d6c7d678634c364ec1154bb7e3f32`.
- SHA-256 v0.1.4:
  `4093f2e0dfcbbbc1c0caf0ed1d9d8902de747aa41e9525840b4755004e791b93`.

Исследованные участки TDDP, factory helper и flash-драйверов в архивном v0.1.4
и официальном образе совпадают байт в байт:
[пункт №008](https://github.com/adsdevdoo/switchlens-sg1218/issues/1#issuecomment-6250781077).
Это подтверждает происхождение исследованного кода из штатной прошивки.
Независимое воспроизведение на неизменённой официальной установке запрашивается у производителя.

## Подтверждённый результат на устройстве

**18.10.2026 в 14:05:00 UTC** владелец запустил PowerShell-скрипт без передачи
учётных данных на одном свитче:

| Операция | Результат |
|---|---|
| Чтение заводского MAC | Получен исходный MAC |
| Запись отличающегося локально администрируемого MAC | Получен ACK |
| Отдельное чтение заводского MAC | Получен новый MAC |
| Запись исходного MAC | Получен ACK |
| Отдельное чтение заводского MAC | Получен исходный MAC |

Результат: `CHANGED_FACTORY_READBACK_WITHOUT_CREDENTIALS_CONFIRMED`.
Восстановление: `ORIGINAL_MAC_READBACK_CONFIRMED`. Ошибок нет.

[Полный вывод владельца и использованный скрипт — №010](https://github.com/adsdevdoo/switchlens-sg1218/issues/1#issuecomment-6250854017).
Доказательство изменения — отдельное чтение нового значения, а не один ACK.

Ранее, **18.10.2026 в 07:55:18 UTC**, первоначальное чтение MAC не получило
ответа; служебный обмен без пароля получил ответ, после чего чтение вернуло
ожидаемый MAC. Последующая проверка записи началась уже при доступном чтении:
служебный обмен в ней не повторялся, свежей перезагрузки перед ней не было.

## Путь в коде и объём записи

TDDP принимает UDP **1040**, ответы отправляет на UDP **61000**.
Обработчик `0xbfc4e238` по opcode 12 переводит состояние 2 в 0 после успешной
отправки ответа, без проверки учётных данных в исследованной ветви.
Opcode 6 передаёт шесть байтов в setter `0xbfc52ff0`, вызывающий helper
`0xbfc52edc`. Opcode 15 читает через `0xbfc54018` из отображённой в память
области заводской flash; для MAC из одних FF предусмотрено значение по умолчанию.

Helper сохраняет 194 байта, запрашивает стирание сектора 508 (номинально
4 КиБ со смещения `0x1fc000`), затем записывает обратно 194 байта.
В проверенном историческом дампе владельца оставшиеся 3902 байта равны FF.
Это не доказывает текущее содержимое всего сектора. Программная защита записи
сама по себе не предотвращает предшествующую попытку стирания; аппаратная
защита не считывалась. См. [журнал, №002–007](https://github.com/adsdevdoo/switchlens-sg1218/issues/1).

## Материалы для воспроизведения

  они не доказывают физическую запись.

Скрипт проверки записи стирает/перезаписывает factory-сектор.
Восстановление — попытка, а не гарантия. Скрипт не отправляет сброс или
перезагрузку и сохраняет результаты после каждого шага.

## Границы проверки и последствия

Подтверждено изменение заводского идентификатора без авторизации клиентом,
имеющим доступ к службе в проверенной сети. После восстановления повторно
прочитаны только шесть байтов MAC; целостность всего сектора отдельно не проверялась.
Сохранение после отключения питания, доступность из Интернета, другие версии
прошивки, выполнение произвольного кода и другие заводские записи не продемонстрированы.
Намеренная закладка не заявляется. Исследованная ветвь TSDP type 3 проверяет
настроенные логин/пароль; универсальный обход TSDP не заявляется.

## Запрос производителю и защита

Просим воспроизвести на официальной V5, определить затронутые версии и сетевую
доступность, отключить ненужные заводские службы в рабочей прошивке либо
проверять авторизацию и права перед каждой заводской операцией.

SwitchLens v0.1.5 содержит защитный патч, отключающий входы TDDP/TSDP.
Это пользовательская мера защиты, не исправление производителя; установка
и проверка этой защиты на устройстве владельца пока не подтверждены.
Ограничение доступа к сети управления уменьшает доступность службы,
но не доказывает исправление прошивки.
