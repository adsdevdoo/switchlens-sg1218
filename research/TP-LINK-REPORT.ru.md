# Черновик для производителя: авторизация заводского управления TDDP

Статус: подготовлен для проверки владельцем; не отправлен. Проверка на устройстве ожидается.

## Устройство и образ

TP-Link TL-SG1218MPE(UN) V5, прошивка 1.0.0 Build 20230616.
SHA-256 официального обновления:
`c9ab17eda7af714f00692d41f440ce84ed0d6c7d678634c364ec1154bb7e3f32`.
Проблема также воспроизводится в производной прошивке SwitchLens v0.1.4.

## Находка и последствия

Обработчик TDDP `0xbfc4e238` допускает служебный обмен, переводящий начальное
состояние 2 в 0 без проверки учётных данных, при успешной отправке ответа.
Последующие проверенные запросы достигают функции сохранения заводских данных
`0xbfc52edc` без проверки учётных данных. При доступности UDP-службы это может
позволить неавторизованное изменение заводских данных. Физическая запись flash,
произвольное выполнение кода и намеренная закладка не продемонстрированы.
Универсальный обход TSDP не заявляется: рассмотренная ветвь type 3 проверяет
настроенные логин и пароль.

## Воспроизведение без обращения к устройству

Из корня репозитория установите зависимости `requirements-dev.txt` и выполните:

```sh
python tools/audit_management_auth.py
```

Проверка выполняет оригинальный MIPS-код в Unicorn: проверяет обнуление BSS при
загрузке, начинает с состояния TDDP 2, выполняет служебный обмен и фиксирует
три вызова сохранения заводских данных. Сохранение и отправка пакетов заменены
заглушками: сети и записи flash нет. Ожидаемый результат: штатная прошивка и
v0.1.4 переходят в 0 и вызывают сохранение; v0.1.5 этого не делает.
См. [доказательства](SECURITY-AUDIT.ru.md) и [результаты](management-auth-results.json).

## Дополнительная проверка на устройстве: обмен и чтение MAC

Скачайте [Confirm-TddpHandshake.ps1](../tools/Confirm-TddpHandshake.ps1).
Закройте Easy Smart Utility, чтобы освободить локальный UDP-порт 61000.
В PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Confirm-TddpHandshake.ps1 -SwitchIP <IP_ВАШЕГО_СВИТЧА>
```

Скрипт отправляет максимум три адресных запроса на UDP 1040: чтение MAC,
служебный обмен при необходимости и повторное чтение MAC. Пароль не передаётся;
записи конфигурации/flash, сброса, перезагрузки и изменения firewall нет.
Внутреннее состояние TDDP в RAM может измениться. JSON содержит байты запросов
и ответов, идентификаторы транзакций, порт отправителя и MAC. Ответ принимается
только от заданного IP с ожидаемыми заголовком, размером и транзакцией.

`HANDSHAKE_AND_MAC_READ_WITHOUT_CREDENTIALS_CONFIRMED` подтверждает сетевой вход
и чтение, **не физическую запись flash**. Если чтение доступно сразу, это
отмечается отдельно. Молчание/ошибки не дают однозначного вывода. Запуск именно
Windows PowerShell ещё должен подтвердить владелец; последовательность запросов
и ожидаемые ответы проверены на трёх образах в MIPS. Успешный результат на
устройстве пока не заявляется. Перед публичным размещением результата скройте
IP/MAC владельца; оригинал при необходимости сохраните для частного отчёта.

## Запрос производителю

Просим проверить сетевую доступность в официальной прошивке V5 и допустимость
доступа к заводским операциям без авторизации. Отключить службу в рабочей
прошивке либо проверять авторизацию и права перед каждой заводской записью.
SwitchLens v0.1.5 защитно отключает входы TDDP/TSDP; это пользовательский патч,
не исправление производителя, и он ещё не проверен на оборудовании.
