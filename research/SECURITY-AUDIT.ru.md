# Проверка безопасности штатного управления — 17 октября 2026

Найдены RC4-кодек с фиксированным ключом и путь TDDP от начального состояния 2
до вызова записи заводских данных без проверки учётных данных.
Переход воспроизведён в MIPS-эмуляторе для штатной прошивки и v0.1.4.
**Намеренная закладка производителя не доказана. Неавторизованная запись
заводских данных по сети на устройстве не продемонстрирована.** В качестве
защитной меры SwitchLens v0.1.5 отключает инициализацию и входные обработчики
TDDP и TSDP.

Объект: TL-SG1218MPE(UN) V5, штатное обновление 20230616, SHA-256
`c9ab17eda7af714f00692d41f440ce84ed0d6c7d678634c364ec1154bb7e3f32`.
Методы: дизассемблирование, ссылки в коде, выполнение оригинальных MIPS-функций
в Unicorn с синтетическими данными. Пакеты на устройство не отправлялись,
реальные учётные данные не расшифровывались. Запись flash и сокеты подменены.

## Находки

| Находка | Доказательства и границы вывода |
|---|---|
| Фиксированный RC4-ключ | 256 байт по файловому смещению `0xcb2e8`, VA `0xbfcd32e8`; SHA-256 `003d481f74298dfb9cd27e69c74405a1bb949af5c5591dedea18c284ea828b54`. Ключ зашит в прошивку и не зависит от пароля владельца. |
| Обратимое хранение учётных данных | Функция `0xbfc47c38` преобразует по 16 байт логина и пароля с одним ключом и новым состоянием RC4 для каждого буфера. Результат MIPS совпал с независимой реализацией RC4; повторное преобразование вернуло исходные данные. Функция `0xbfc543a4` читает настроенные учётные данные из RAM/flash и вызывает кодек. Это не хеширование пароля. |
| Управление TSDP | Инициализация `0xbfc47cf0` регистрирует обработчик `0xbfc48db0` и открывает UDP 29808. Обработчик вызывает RC4 до последующих проверок заголовка/сессии. Ключ не обеспечивает секретность, уникальную для устройства. Обход авторизации для всех операций TSDP не установлен. |
| Управление TDDP | Инициализация `0xbfc4d668` через `0xbfc4d6f8` регистрирует обработчик `0xbfc4e238` и открывает UDP 1040. Дополнительная проверка ниже воспроизводит переход из начального состояния 2 в 0, затем три вызова записи заводских данных без учётных данных. Успешная отправка ответа моделируется. Доступность пути по реальной сети ещё не проверена. |
| Сохранение заводских данных | Функция `0xbfc52edc` копирует данные из `0xb41fc000`, меняет выбранные байты, вызывает стирание сектора и записывает обратно `0xc2` байта. Эмулятор останавливает путь на этой функции и фиксирует вызовы; реальной записи flash нет. |
| Авторизация HTTP | Обработчик входа `0xbfc3f8e0` сравнивает настроенные учётные данные, включая второй путь преобразования представления. Отдельный универсальный пароль в рассмотренном пути не выявлен. Это не исключает скрытые учётные записи в других местах. Сам HTTP остаётся незашифрованным. |

В опубликованном [исследовании Easy Smart](https://geekly.dev/easy-smart-report-main/)
описаны проблемы RC4 с постоянным ключом у других ревизий, включая SG1218MPE V1–V4.
V5 там не перечислена. Выводы о V5 выше получены из нашего конкретного BIN;
нельзя автоматически переносить CVE других устройств на этот коммутатор.

## Уточнение: переход из начального состояния и авторизация TSDP

В первоначальном отчёте v0.1.5 состояния TDDP 0/1 задавались принудительно;
способ перехода в них не был доказан. Новый [офлайн-аудит](../tools/audit_management_auth.py)
и [результаты](management-auth-results.json) закрывают именно этот пробел анализа.
Проверяются SHA-256 штатного BIN, v0.1.4 и v0.1.5; сами релизные BIN не менялись.

**TDDP:** состояние по адресу `0xbf0015c0` изначально равно 2. Загрузочный цикл
`0xbfc08684..0xbfc086a4` обнуляет BSS, включая счётчик `0xbf013690`;
отдельное выполнение этого цикла подтвердило нулевой счётчик и сохранение
состояния 2. В обработчике `0xbfc4e238` ветвь `0xbfc4e314..0xbfc4e384`
принимает управляющий запрос с opcode 12/type 1. Если счётчик неотрицательный,
а функция отправки ответа возвращает успех, обработчик записывает состояние 0.
Проверки пароля или HTTP-сессии в этой ветви нет.

Начиная с состояния 2 из образа, без принудительной установки 0, эмулятор
затем достигает функции `0xbfc52edc` для каждой проверяемой команды:

| Opcode | Смещение внутри заводских данных | Длина |
|---|---|---|
| 6 | `0x00` | 6 байт |
| 14 | `0x96` | 40 байт |
| 11 | `0x06` | 128 байт |

До управляющего обмена эти команды игнорируются. Неверный тип управляющего
запроса и ошибка отправки ответа оставляют состояние 2. Получение учётных
данных не вызывается. Функция сохранения перехвачена до выполнения: стирания
и записи flash нет. Штатный BIN и v0.1.4 ведут себя одинаково; v0.1.5 сразу
возвращает управление, без ответов и вызовов записи. Это подтверждает
**отсутствие авторизации в рассмотренном пути заводского управления TDDP**,
но не доказывает умысел производителя.

**TSDP:** шифрование фиксированным ключом не означает, что любые команды
обходят вход. Ветвь type 3 проверяет 16-битный токен сессии, разбирает TLV
логина/пароля и вызывает сравнение `0xbfc47e74` до диспетчеризации команд.
Новые проверки выполняют оригинальное расшифрование и разбор с самого входа
обработчика, используя синтетическую учётную запись и MAC. Отсутствие учётных
данных отклоняется (код 3); неверный пароль отклоняется (код 7); верные данные
достигают `0xbfc49124`, сразу после успешной проверки. Неверный токен вызывает
возврат до получения учётных данных. Запрос type 1 на чтение TLV пароля
`0x0202` без авторизации отклоняется (код 2). Это отдельные запросы корректного
формата, **не** полный аудит повреждённых пакетов или обходов авторизации.
У type 0/1 есть отдельная обработка обнаружения/чтения до входа; само её
наличие не доказывает произвольное изменение настроек без пароля.

Всего пройдены 33 ограниченные проверки трёх образов: 3 загрузочного цикла,
9 последовательностей TDDP, 6 отрицательных контролей TDDP и 15 случаев TSDP.
Выполнение TSDP намеренно останавливается в точках отказа или успешной
авторизации. Создание/привязка сокетов и чтение настроенной учётной записи
моделируются. Полная загрузка, доставка пакетов и физическая запись не эмулируются.

Проверка владельца на v0.1.4 не получила подходящий ответ на одиночный запрос
чтения MAC без этого управляющего обмена. Результат не подтверждает и не
опровергает найденный путь: в состоянии 2 эмулятор тоже игнорирует прямой
запрос. Реальное состояние устройства и доставка пакета тогда не наблюдались.

Для локального воспроизведения с Python-зависимостями разработки репозитория:

```sh
python tools/audit_management_auth.py
```

## Защита в v0.1.5

| Смещение в файле | Точка входа | Изменение |
|---|---|---|
| `0x3fcf0` | Инициализация TSDP | Немедленный возврат, без регистрации/привязки сокета |
| `0x45668` | Инициализация TDDP | Немедленный возврат, без регистрации/привязки сокета |
| `0x40db0` | Приём TSDP | Возврат до обращения к входным данным |
| `0x46238` | Приём TDDP | Возврат до обращения к входным данным |

Каждый вход заменён на `jr ra; move v0, zero` с учётом delay slot.
Сборщик проверяет исходные байты и разрешает изменения только в заданных областях.
Сообщения загрузки исправлены. Инициализатор HTTP и обе штатные проверки
авторизации HTTP не изменены. Кодек пароля сохранён для совместимости входа и
конфигурации: замена ключа без миграции сохранённых данных сломала бы вход.

Фирменная утилита TP-Link больше не сможет обнаруживать и настраивать свитч
через эти службы. Веб-управление, JSON с авторизацией и UART сохранены.
Отключены только две прикладные службы; настройка ASIC для DHCP/IGMP сохранена.
Это не отключение всего UDP-трафика.

- [Скрипт аудита](../tools/audit_security.py): синтетическое преобразование RC4
  туда и обратно, 12 сочетаний команд/состояний TDDP и список строк HTTP-маршрутов.
- [Машиночитаемые результаты](../releases/v0.1.5/security-audit.json).
- [Проверки защиты](../tests/test_security.py) и [результаты](../releases/v0.1.5/security-test-results.json): штатные функции открывают ожидаемые UDP-порты; изменённые не создают сокеты; входные обработчики возвращаются даже с недоступным адресом входных данных; участок загрузки продолжает работу и сохраняет условный запуск HTTP; блоки авторизации, кодека пароля и хвост конфигурации не изменены.
- [BIN v0.1.5, хеши и все 26 MIPS-проверок](../releases/v0.1.5/README.ru.md).

Для конкретного BIN v0.1.5 ещё нужна установка и проверка сети на устройстве.
Это ограниченные проверки процессорного кода, не полная загрузка устройства и
не доказательство отсутствия уязвимостей. Полный аудит косвенных вызовов,
скрытых пользователей, удалённого выполнения кода и всех сетевых парсеров
не выполнен. Строки `/httpupg.cgi`, `/reset.cgi`, `/conf_restore.cgi` обозначают
обычные функции управления; само их наличие не доказывает скрытый доступ.

Дальше: ограничить доступ к сети HTTP-управления; при необходимости отдельно
спроектировать миграцию с обратимого хранения пароля; продолжить проверку
остальных обработчиков управления. Хранение учётных данных с фиксированным
ключом и открытый HTTP этим патчем **не исправлены**. Реальные пароли и cookies
при проверке не публиковать.
