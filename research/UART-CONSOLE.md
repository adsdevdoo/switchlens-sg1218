# Штатная UART-консоль: код есть, диспетчер отключён

Дата: 17.10.2026. **Проверено статически по сохранённому дампу**;
электрический RX и работа изменённого образа этим не проверены.

## Результат

В штатном runtime присутствуют обработчик CLI и приглашение `RTK# `,
но его периодический вызов закрыт битом 0 слова по VA `0xbfcff018`.
В сохранённом образе слово равно **`0x00000000`**. В этой ветви программа
возвращается до опроса UART и обработки Enter.

Поэтому отсутствие реакции на Enter после штатной загрузки **ожидаемо
для найденного пути**. Такой тест не позволяет оценить исправность RX,
контакта pin 2 или пайки R41/R42. Утверждать, что RX исправен, тоже нельзя.
Повторять тест и перепаивать резисторы только из-за тишины оснований нет.

## Исходные байты

- [Исходный экспорт](../backups/original/2026-10-17/README.md):
  SHA-256 `b80e10d5fb75ee2d4d8a45dba305090fe204d521c96d24202876273959589a87`.
- Обе содержащиеся в нём копии runtime по SPI-смещениям `0x8000` и `0x100000`
  совпадают с исходным update BIN размером 1 013 324 байта и SHA-256
  `c9ab17eda7af714f00692d41f440ce84ed0d6c7d678634c364ec1154bb7e3f32`.
- Ниже runtime file offset отсчитывается от начала update BIN с его заголовком;
  SPI offset — от начала полного дампа. Это разные системы смещений.

## Прослеженный путь

1. Runtime `0x26988..0x2699c` регистрирует callback `0xbfc2dec8`
   через `0xbfc2df70` в таблице периодических функций.
2. Callback читает слово `0xbfcff018`, проверяет bit 0 и при нуле
   обходит вызов CLI `0xbfc2cd0c`.
3. Обработчик CLI в runtime `0x24dd8..0x24df8` опрашивает наличие символа
   через `0xbfc1146c` и читает его через `0xbfc1147c`. Эти обёртки ведут
   к UART status/data access, но при выключенном диспетчере не достигаются
   по прослеженному пути.
4. Runtime `0x24df8..0x24e3c` обрабатывает LF (`0x0a`) и CR (`0x0d`),
   в том числе печатает приглашение `RTK# ` при пустой строке.
   Строка находится по runtime offset `0xd37b0`.

Ключевой блок (с учётом MIPS branch delay slot):

```text
runtime off  VA          instruction
0x25ed0      bfc2ded0    lui   v0, 0xbfd0
0x25ed4      bfc2ded4    lw    v0, -0xfe8(v0)   # VA 0xbfcff018
0x25ed8      bfc2ded8    andi  v0, v0, 1
0x25edc      bfc2dedc    beqz  v0, 0xbfc2def0
0x25ee0      bfc2dee0    lw    ra, 0x14(sp)     # delay slot
0x25ee4      bfc2dee4    jal   0xbfc2cd0c       # skipped when bit 0 = 0
0x25ee8      bfc2dee8    move  a0, zero
0x25ef0      bfc2def0    move  v0, zero
0x25ef4      bfc2def4    jr    ra
0x25ef8      bfc2def8    addiu sp, sp, 0x18
```

| Объект | Смещение / значение |
| --- | --- |
| Слово флага в update BIN | `0xf7018`: `00 00 00 00` |
| То же слово в первой копии полного SPI | `0xff018`: `00 00 00 00` |
| То же слово во второй копии полного SPI | `0x1f7018`: `00 00 00 00` |
| Известная CRC-область runtime | `[0x10, 0xf7000)`; слово флага лежит вне неё |

Функция `0xbfc2de90` также разбирает биты того же слова в таблицу
разрешений CLI-команд. Включение одного диспетчера не доказывает доступность
всех команд и тем более рабочего восстановления.

## Загрузчик

В нормальной ветви SPI `0x1730..0x17c0` (RAM VA `0xbf003038..0xbf0030c8`)
загрузчик печатает `check runtime img`, проверяет заголовок, печатает
адрес и передаёт управление на `0xb4008010`. В этом блоке нет ожидания
Enter или выбора меню. UART input helpers присутствуют в другом коде;
это не доказательство доступного меню. Полное отсутствие альтернативных
путей остановки/восстановления **не утверждается**.

## Что делать дальше

1. Сохранить рабочий приём UART для наблюдения за загрузкой.
2. Подготовить и проверить путь возврата штатного содержимого программатором
   по [LAB](../docs/LAB.md); наличие интерактивной UART-консоли не считать
   установленным или обязательным свойством штатного образа.
3. Диагностический вариант **собран и проверен только в CPU-эмуляции**:
   [v0.1.1-experimental-uart](../releases/v0.1.1-experimental-uart/README.md).
   Он включает диспетчер и разрешения CLI двумя инструкциями внутри CRC-области,
   сохраняя слово параметра без изменений. Принятие web-обновлением и загрузка
   на железе ещё не проверены.
4. После проверенного восстановления и остальных критериев ROADMAP —
   отдельное стендовое испытание SwitchLens.

Оригинал дампа и BIN v0.1.0 не менялись. Новый диагностический BIN хранится отдельно.

## Воспроизведение

```bash
python3 tools/audit_uart.py backups/original/2026-10-17/GD25Q16B-xgpro-original.bin
```

Скрипт только читает файл, сверяет SHA-256, обе копии runtime и байты
проверенного блока, извлекает адрес/значение/маску и печатает JSON.
Результат: [uart-console-evidence.json](uart-console-evidence.json).
Аудит инструкций выполнен Capstone 5.0.9 с картой RAM/flash из документации
репозитория. Это статический разбор, не эмуляция оборудования и не стендовый тест.
