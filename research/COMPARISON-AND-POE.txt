Вывод-гипотеза: появление SignCheck нельзя связывать с февральским обновлением — оно существовало до него. Однако полностью исключить дополнительные проверки загрузчика по runtime-образам нельзя.

Гипотеза: изменение связано с криптографией управления; полный протокол не восстановлен. Отсутствие диагностических строк в июньском образе НЕ доказывает удаление RSA, откат защиты или уязвимость.

Включить PoE в тот же JSON с сетевыми счётчиками. Ничего не записывать и не переключать.
Проверено для20230616: router0x34920..0x34948 переводит /PoeConfigRpm.htm на VA0xbfc42910 (file0x3a910).
Проверено: handler читает RAM-структуру0xbf0143e0. Общие поля:
 port_count +0x00;
 system_power_limit +0x14;
 system_power_limit_min +0x18;
 system_power_limit_max +0x1c;
 system_power_consumption +0x20.
Источник: disassembly0x3a9f4..0x3aa84.
Проверено: web handler ограничивает вывод потребления сверху лимитом, остаток считает max(limit-consumption,0). Для JSON желательно отдельно иметь сырое значение/признак качества, а не терять диагностику через молчаливое ограничение. Это проектное предложение, не готовый патч.
Проверено: поля портов читаются с шагом0x30:

Источник: disassembly0x3aab8..0x3ace8. Здесь указаны адреса первого порта, не разрешение читать их на боевом устройстве.
Проверено: форматируемые массивы также включают pdclass@string0xd6e80 и powerstatus@string0xd6e8c; точные RAM-смещения этих двух полей в этом дополнении не установлены.
Проверено: JS printSpanStr@0xb6938: power/10, voltage/10; current без масштабирования; заголовок Current(mA) находится в HTML0xb43f8..0xb8034. Общий бюджет/потребление/остаток JS также делит на10.

Проверено: priority0/1/2 -> High/Middle/Low.
Проверено: powerstatus0..9 -> OFF, TURNING-ON, ON, OVERLOAD, SHORT, NOSTANDARD-PD, VOLTAGE-HIGH, VOLTAGE-LOW, HARDWARE-FAULT, OVERTEMPERATURE. Неизвестный код показывается---.
Проверено: нулевые измерения power/current/voltage интерфейс отображает---. Семантика реального нуля против недоступного измерения не доказана; в JSON предусмотреть raw и validity/null, не назначать смысл без проверки.

ПРОЕКТ JSON (гипотеза реализации)
Общий poe: power_limit_w, power_consumption_w, power_remaining_w, validity.
Для портов1..16: poe.enabled, status_code, status, power_w, current_ma, voltage_v, pd_class, priority, power_limit_mode, power_limit_w (null приAuto), power_limit_raw.
Для портов17/18: poe:null (не выдавать отсутствиеPoE за выключенное питание).
Код статуса сохранять вместе с текстом. Не выдавать запрошенную конфигурацию enabled за факт питания status=ON.
Читать существующий RAM-кэш, который использует панель; его обновление/согласованность и время последнего измерения ещё надо исследовать. Предложение не предполагает новых команд PoE-контроллеру.
