# Easy Smart Configuration Utility: статический разбор протокола

В выгрузке пользователя подтверждены протокол управления с полями логина/пароля и старый ключ шифрования, полностью совпадающий с ключом штатной прошивки. **Новый обход авторизации этим не доказан.** Ранее подтверждённое на железе изменение заводского MAC без пароля относится к отдельной службе TDDP.

Дата разбора: 2026-10-18. Анализ выполнен офлайн: приложение, Java-классы и сетевые запросы не запускались.

## Транспорт и заголовок

Имена методов ниже указаны относительно `com/tplink/smb/easySmartUtility/`.

По `transfer/i.<clinit>`, `transfer/The.bb` и `transfer/V.bd`:

| Вариант клиента | UDP-порт назначения | Локальный UDP-порт |
| --- | ---: | ---: |
| Обычный | 29808 | 29809 |
| Альтернатива при ошибке привязки порта | 62576 | 62577 |

Адрес назначения — 255.255.255.255. Это возможности клиента; доступность каждого варианта на свитче не проверялась.

`transfer/PacketHead.toArray` формирует заголовок длиной 32 байта. Методы `transfer/TLV.F(S)` и `i(I)` записывают многобайтные числа в big-endian.

| 16 | 4 | Поле ошибки |

## Запросы, учётные данные и вход

| Идентификатор | Что установлено | Источник |
| --- | --- | --- |
| Opcode 0 | Режим y, путь обнаружения устройств | PacketHead.Code, V$1.succeeded |
| Opcode 1 | Другие запросы, включая запрос токена | PacketHead.Code, From |
| Opcode 3 | Режим A, запросы управления с учётными данными | PacketHead.Code, The.ba |
| Ответы 2 / 4 | Принимаются для y/z и A соответственно | PacketHead.I |
| TLV 0x0200 | Логин из DeviceInfo | The.ba |
| TLV 0x0202 | Пароль из DeviceInfo | The.ba |
| TLV 0x0210 | Сгенерированный ключ после обработки transfer/I.I | RSAKeyBean.buildSetRequest |
| TLV 0x0901 | Запрос токена | From.init |
| 0xFFFF и нулевая длина | Конец данных | From.init |

Контроллер входа сначала отправляет RSAKeyBean. При распознанном результате 0x1002 он выбирает NEW_RC4_8 для MAC устройства. Затем берёт введённые пользователем логин и пароль, собирает SwitchLoginBean и отправляет запрос. Здесь описан код клиента; живой обмен со свитчем в этом исследовании не перехватывался.

Добавление пароля клиентом само по себе не доказывает проверку на каждом серверном пути. Наличие общего ключа шифрования также не доказывает обход этих проверок.

## Шифрование

В коде явно названы OLD_RC4 и NEW_RC4_8. Первый использует состояние RC4 из 256 элементов и общий ключ. Второй использует состояние из 8 элементов; строка ключа длиной восемь символов создаётся через конструктор с **SecureRandom**, несмотря на тип поля Random.

Константа из 264 байт в `transfer/of.aM` расшифрована переносом алгоритма `transfer/mine.V`: 32 раунда, знаковый сдвиг Java и 32-битное переполнение. После удаления восьми байт дополнения все 256 байт совпали с диапазоном штатного BIN **[0xCB2E8, 0xCB3E8)**. Обратное шифрование восстановило исходную константу.

- SHA-256 восстановленного ключа: `003d481f74298dfb9cd27e69c74405a1bb949af5c5591dedea18c284ea828b54`.
- SHA-256 исходного BIN: `c9ab17eda7af714f00692d41f440ce84ed0d6c7d678634c364ec1154bb7e3f32`.

Старый ключ извлекается из распространяемого ПО и не является индивидуальным секретом свитча. Малое состояние нового режима требует отдельной криптографической оценки. Ни один из этих фактов не устанавливает режим текущего соединения и не доказывает новую эксплуатацию устройства.

## Ложные следы и открытые вопросы

В классе верхнего уровня Tempest есть admin/admin, но он выводит «Switch Simulation is Running.» и работает с моделями симулируемых свитчей. Его оболочка присутствует; включение симулятора в выпущенной программе не установлено. Эти строки **не подтверждают скрытую учётную запись свитча**. Строка password в transfer/mine.main используется в демонстрации шифрования.

Поиск в этих 100 классах не установил назначение factory field40, связь с его известным значением или вызов SHA1/MessageDigest. Флаг getIsFactory в интерфейсе и сообщение об ошибке записи flash при обновлении такой связи не доказывают. В выгрузке нет многих классов, включая DataBean, SwitchLoginBean и DeviceInfo; это не полный аудит утилиты и не полный каталог команд.

Ранее пользователь подтвердил на заявленной SwitchLens v0.1.4 изменение заводского MAC без пароля, чтение изменённого значения и восстановление оригинала. Сохранение после перезапуска и выполнение произвольного кода не проверялись. Этот результат сохраняет силу независимо от разбора утилиты.

Следующий полезный материал — отсутствующие классы сборки запросов и DeviceInfo для точной карты TLV. Назначение factory field40 следует устанавливать по использующему его коду прошивки.

Отдельный полный листинг байткода не опубликован: автоматическая проверка отклонила публикацию из-за проприетарного кода и встроенного криптографического материала. Скрипт позволяет воспроизвести листинг локально из уже загруженных пользователем данных.
