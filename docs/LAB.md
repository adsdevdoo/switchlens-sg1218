# Подготовка отдельного стенда

Это план, а не инструкция к уже определённым контактам платы. Данных о
распиновке UART, электрических уровнях и точной маркировке SPI пока недостаточно.

1. Подтвердить именно V5.0 по наклейке и фото платы, не V5.6.
2. На отключённом от сети питания устройстве сделать чёткие фото обеих сторон
   платы, маркировок SoC, SPI и предполагаемых UART-площадок. Блок питания
   содержит сетевое напряжение; работы с его первичной стороной не требуются.
3. Определить GND и измерить сигнальные уровни до подключения UART. Потребуются
   мультиметр и UART-адаптер с подходящими логическими уровнями. Не подавать
   питание через VCC адаптера; конкретный уровень не угадывать.
4. Выбрать программатор и адаптер к корпусу/напряжению конкретной SPI-микросхемы
   после чтения её маркировки. Нельзя предполагать совместимость прищепки без
   проверки схемы питания и отсутствия подпитки платы.
5. Снять полный дамп несколько раз и сравнить SHA-256. Сохранить оригиналы
   вне Git вместе с маркировкой микросхемы и журналом программатора.
6. Получить UART boot log и консоль загрузчика. Конкретные команды чтения,
   записи и восстановления определить по наблюдаемому загрузчику.
7. Проверить восстановление полного дампа на стенде и возврат штатной работы.
   Только после отдельного отчёта и решения переходить к изменённому образу.

Для испытаний понадобятся отдельный V5.0, компьютер для UART/программатора,
Ethernet-узлы для нагрузки и реальные PoE-потребители. Боевой коммутатор
для этих работ не используется. Дампы и UART-логи могут содержать уникальные
данные; в репозиторий попадают только необходимые обезличенные выдержки.
