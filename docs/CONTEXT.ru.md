# SwitchLens: контекст для продолжения работы

Обновлено **17.10.2026 после теста GPIO27 на v0.1.2 и продолжения анализа кода**.
Это точка входа для следующего чата; актуальные данные — в `main`.

## Цель

Read-only `GET /stats.json` в штатном HTTP-сервере TL-SG1218MPE(UN) V5.0
для последующего сбора в Prometheus и отображения в Grafana. SNMP не входит
в текущую цель. Exporter и dashboard пока не созданы.

**[Подробный справочник JSON](JSON-API.ru.md)** ·
**[Успешное испытание: сообщения, скриншоты, логи и оба JSON](evidence/2026-10-17-switchlens/README.ru.md)**.

## Что уже произошло

1. Сохранены исходный экспорт SPI, официальные прошивки V5 и даташиты.
2. Получен штатный UART boot log: R41/R42 по 0 Ом 0402, 38400 8N1.
3. Статически найден программно выключенный CLI. Тишина после Enter
   не являлась доказательством плохой пайки RX.
4. Выпущен **v0.1.1-experimental-uart**: JSON-payload v0.1.0 + две инструкции
   включения штатного CLI и пересчитанная CRC. Офлайн: 20 MIPS-тестов,
   host-тесты, ASan/UBSan; [отчёт](../releases/v0.1.1-experimental-uart/FINAL-CHECK.md).
5. Владелец выполнил штатное web-обновление. Получены `Image recover done!`,
   переход в runtime, `SignCheck Pass.`, `RTK#` и завершение `code init`.
6. Владелец ввёл `help` и получил список команд: **двусторонний UART работает**.
7. Получены два полных `/stats.json`: оба проходят схему, все 18 портов,
   изменяются счётчики и `uptime_ticks_raw`.

Не возвращаться к утверждениям «прошивка ещё не запускалась», «UART только
выводит текст» или «JSON только в эмуляторе»: для этого экземпляра они устарели.

## Стенд

Один свитч владельца, пока не введённый в эксплуатацию. Внешняя/веб-версия V5.0,
на плате Ver:5.40 и PCB 2060500612. RTL8214FC на фото не доказывает модель SoC.
Флеш U6 GD25Q16BSIG, 16 Мбит / 2 МиБ.

| Параметр | Подтверждённый статус |
| --- | --- |
| R41/R42 | По 0 Ом, 0402; установка и прозвонка сообщены владельцем |
| J2 pin 1 | TX свитча → RXD адаптера |
| J2 pin 2 | RX в описанном подключении; `help` подтвердил двусторонний обмен, нового фото проводов нет |
| J2 pin 3 | GND по проверке владельца |
| J2 pin 4 | 3,3 В по измерению владельца; питание адаптера сюда не подключается |
| UART | CP2102, COM3, 38400, 8N1, Flow control None |

Нумерация J2 — владельца при измерениях; ориентация по фото не универсальна.
«Выставил 3.3 на адаптере» — сообщение о настройке, не независимый замер TXD.
[LAB](LAB.ru.md), [UART](../research/UART-CONSOLE.ru.md).

## Восстановление и решение владельца

Исходный экспорт:
`backups/original/2026-10-17/GD25Q16B-xgpro-original.bin`,
2 097 424 байта; первые 2 097 152 — массив SPI, затем 272 байта Xgpro.
SHA-256 `b80e10d5fb75ee2d4d8a45dba305090fe204d521c96d24202876273959589a87`.
Обе runtime-копии совпали с официальным update BIN; это не два независимых чтения.
Владелец использовал T56/Xgpro, прочитал/проверил микросхему и припаял обратно.

**Владелец отказался от повторной выпайки ради предварительного теста отката.**
Не предлагать её снова как обязательный шаг. Запись дампа с последующим
восстановлением, отдельные UID/OTP и UART/TFTP recovery ещё не проверены.
Работа `RTK#` не доказывает аварийную консоль загрузчика.

## Текущий приоритет: код охлаждения и мониторинг GPIO26

Подготовлен [v0.1.2 BIN](../releases/v0.1.2-cooling/README.ru.md): команды `cool status`,
`cool test 0`, `cool test 1`, `cool auto`; удержание 100 raw-тиков и возврат
к штатному гистерезису. 24 MIPS-теста пройдены; владелец подтвердил CLI сборки и GPIO27=0 в активном тесте.
`/stats.json` дополнен read-only `cooling`, RPM/здоровье остаются null.
[Полная реализация, команды и пределы](COOLING-CONTROL.ru.md).

У владельца Noctua NF-A4x20 PWM 12 В, подключены три стандартных провода.
Один и тот же вентилятор не стартует в обоих разъёмах, но работает после толчка.
Direction `0x39000000`, data `0x39780000`, FAN оранжевый; один крутится, другой нет.
Ручной переход data на `0x31780000` и обратно сопровождался сообщением,
что один «вроде» замедлился; второй не запустился. Связь уровня со скоростью не доказана.
Обрезанное `reg flashget 0x1` повесило старую консоль; новая обёртка проверяет аргументы.
Владелец отказался от измерений и разрешил программный тест. Не повторять запрос мультиметра
или уже выполненные чтения как условие продолжения. Активный `cool test 0;cool status`
показал GPIO27=0 и остаток 100 тиков; отдельный вывод auto — GPIO27=1.
Владелец не заметил явного улучшения вентиляторов. Аппаратный JSON v0.1.2 ещё не получен.
[Продолжение анализа](../research/COOLING-PATHS.ru.md) установило шину PoE и в 32
синтетических случаях общего опроса подтвердило: GPIO26 меняет LED, но не
алгоритм выхода. Другой команды скорости в проверенных путях не найдено.
Объяснить историю сырого GPIO26, режимы индикации и возможный общий сигнал
проблемы; не объявлять RPM, здоровье каждого вентилятора или полярность ошибки.

## Что делать дальше

[Расширенный аудит GPIO](../research/GPIO-INVENTORY.ru.md): прежние 23 прямые
ссылки записи не были полным аудитом GPIO. GPIO19/20 выбирают copper/fiber,
GPIO21 участвует в сбросе конфигурации. У драйвера с именем RTL8231 есть
вычисляемый указатель записи в обработчике оптических модулей. Для ID платы
0x43, выбранного по PHY c984, опрос идёт по ветке внутренних GPIO. Штатные
настраиваемые входы и маскированные записи отключены. Все 32 бита снимка
описаны, но физическая распиновка и все вычисляемые пути ещё не установлены.
Дополнительной команды скорости не найдено. Не объявлять внешний обработчик
записи неиспользуемым только из-за отсутствия прямых вызовов. BIN не менялись.

1. Проверить PoE с реальным потребителем и сравнить JSON со штатной страницей.
2. Сверить настройки/счётчики и физическую нумерацию портов; исследовать discards.
3. Измерить raw uptime по внешнему времени, не назначая единицу заранее.
4. Испытать повторный опрос под нагрузкой, обрывы/медленных клиентов,
   сброс/переполнение и длительную работу. Откат остаётся отдельной неизвестной.
5. На подтверждённых полях строить сбор метрик; решение о вводе отдельно.
