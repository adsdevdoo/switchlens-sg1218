# HTTP-авторизация и сбор статистики

## v0.1.6: статистика без веб-сессии

Открыт только точный **`GET /stats.json`**. Логин, пароль, cookie, токен и
предварительный запрос не нужны. Панель и административные адреса сохраняют
штатную форму входа, cookie `H_P_SSID` и проверку IP клиента.

```powershell
curl.exe --connect-timeout 5 --max-time 15 -D - http://192.168.1.3/stats.json
```

В Linux/macOS используйте `curl`. Не добавляйте `-u`, `-b`, `-c`, Authorization
или запрос входа. Ожидается HTTP 200, `Content-Type: application/json`,
`Cache-Control: no-store`, `X-SwitchLens-Build: v0.1.6`, полный JSON схемы 1
с 18 портами. Заголовка `Set-Cookie` быть не должно.

Запрос статистики не создаёт/заменяет сессию, не меняет её cookie/IP и не
продлевает срок, даже с IP браузера и действующей cookie. Сборщик с другого IP
может работать одновременно с панелью. Обычное истечение сессии сохраняется:
опрос статистики не удерживает пользователя в панели.

Query-параметры, другой регистр, суффиксы, кодированные варианты пути и другие
методы исключения не получают. Например: `/stats.json?x=1`, `/Stats.json`,
`/stats.json/`, `/stats.jsonx`, `POST /stats.json`, `HEAD /stats.json`.
Они идут в штатный обработчик. Метрики доступны любому узлу, имеющему доступ
к HTTP-порту управления; размещайте его в предназначенной для этого сети.

## Опрос и проверка данных

Начните с одного запроса раз в 30 секунд без наложения запросов сборщика.
Это начальный интервал, а не измеренный предел производительности.
Принимайте только полный JSON по [схеме](../schema/stats.schema.json).
HTTP 200 со страницей входа — ошибка. Сетевые ошибки и повреждённый JSON —
пропуск данных, а не нулевые счётчики. Автоматический вход для исправления
ошибки статистики не нужен.

Счётчики остаются десятичными строками; используйте целые без потери точности.
`null` означает недоступное значение. Скорость считайте по двум успешным
замерам и времени сборщика; при уменьшении счётчика/перезагрузке начните новый
интервал. `system.firmware_version` сохраняет строку TP-Link; номер SwitchLens
проверяется заголовком `X-SwitchLens-Build` или UART-командой `cool status`.

## Почему v0.1.3 не работала

v0.1.3 меняла сравнение пути входа по смещению `0x33770` во внутреннем роутере
`0xbfc3b740`. Но вызывающий обработчик `0xbfc3ce48` раньше проверял IP и
подменял путь на `Unauth`. Старые тесты начинались после этой проверки.
На устройстве владелец продолжал получать форму входа. В v0.1.4 ошибочный
патч удалён. В v0.1.5 отключены TDDP/TSDP, но статистика требовала сессию.

v0.1.6 заменяет только первые восемь байтов внешнего обработчика `0xbfc3ce48`
переходом на проверку точного запроса. Проверяются метод/путь после разбора
и исходный префикс **`GET /stats.json `**. Затем вызывается прежний защищённый
по стеку JSON-обработчик, до проверки или продления сессии. Остальные запросы
выполняют две вытесненные инструкции пролога и продолжают штатную функцию
с `0xbfc3ce50`. Внутренний блок проверки cookie не менялся.

Исходная строка важна: парсер `0xbf01d05c` сохраняет путь без query в request+8
и распознаёт GET по трём символам. Одной проверки этих полей недостаточно:
она пропустила бы query и `GETX`. Проверяются также raw-буфер и указатель пути
в +0x88/+0x8c. Штатная ветка для совпавшего IP обновляет таймер `0xbf011670`
значением 600; путь статистики её не выполняет. Нового глобального флага нет.

## Проверки и ограничения

[Тест HTTP](../tests/test_anonymous_http.py) исполняет оригинальный MIPS-парсер,
изменённый внешний обработчик и штатную авторизацию для остальных запросов.
Сверяются cookie, флаг, IP, таймер и остальные байты SRAM: разрешены только
стек и буфер HTTP-ответа. Проверяются отсутствие сессии, другой IP,
отсутствующая/неверная/верная cookie, чередование панели и сборщика,
административные GET/POST, похожие пути/методы, сбой отправки и v0.1.5 как
контроль, воспроизводящий отказ анонимному запросу.

Сокеты и MMIO синтетические. Чередование запросов не доказывает работу реальных
параллельных TCP-соединений и прерываний. Установка/LAN-проверка v0.1.5 и v0.1.6
не заявляется. Последняя подтверждённая установленная версия — v0.1.4.

## Короткая проверка Windows на устройстве

1. Установить [BIN v0.1.6](../releases/v0.1.6/README.ru.md) через штатную страницу
   обновления. После перезагрузки проверить номер сборки в HTTP/UART.
2. Выйти из панели. Выполнить curl выше без cookie — должен прийти JSON.
3. Войти в панель на компьютере A. На **компьютере B с другим исходящим IP**
   запустить [Test-AnonymousStats.ps1](../tools/Test-AnonymousStats.ps1):

   ```powershell
   powershell -NoProfile -File C:\tmp\Test-AnonymousStats.ps1 -Switch 192.168.1.3 -Count 60 -IntervalSeconds 2
   ```

4. Во время опроса переходить по страницам/обновлять панель на A. Повторного
   входа быть не должно. Скрипт проверяет версию/JSON/отсутствие Set-Cookie
   и безопасные отрицательные URL; отчёт и последний JSON сохраняются в `C:\tmp`.
5. На B административные страницы должны показывать вход/отказ. Для отдельной
   проверки срока оставить панель без действий на обычное время её тайм-аута,
   продолжая опрос с B; сессия должна истечь как обычно.

Второй терминал на A не проверяет случай другого IP. В текущем обсуждении разработки v0.1.6 записать оба IP, маркеры загрузки `HTTPD ready; TSDP disabled` / `TDDP disabled`,
работу панели, UART `cool low/fast/auto/status`, переключения портов и PoE.
