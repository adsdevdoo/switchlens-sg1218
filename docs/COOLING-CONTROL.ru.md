# Временные тесты охлаждения — v0.1.2

**Текущий результат:** проблемный вентилятор заменён на штатный; оба вращаются, `cool test 0` ускоряет оба. Упоминания отсутствия эффекта/стоящего вентилятора ниже относятся к прежним тестам. [Новые наблюдения и дальнейшие действия](evidence/2026-10-17-cooling/README.ru.md).

v0.1.2 добавляет команды `cool` и блок `cooling` только для чтения в `/stats.json`.
Владелец подтвердил её CLI и чтение GPIO27=0 во время активного теста;
наблюдался также автоматический режим. Явного улучшения работы вентиляторов нет.
Аппаратный результат JSON v0.1.2 впереди; JSON v0.1.1 уже проверен. [BIN и хеши](../releases/v0.1.2-cooling/README.ru.md).

## Наблюдения владельца до этой сборки

Установлены Noctua NF-A4x20 PWM, 12 В, 4-pin, подключены три стандартных провода;
PWM не подключён. Один и тот же вентилятор не стартует в обоих разъёмах,
но вращается после толчка. Один крутится, второй стоит; FAN горит оранжевым.

Прочитаны direction `0x39000000` и data `0x39780000`: GPIO26 — вход с уровнем 0,
GPIO27 — выход с уровнем 1. Повторные чтения data ничего не изменили.
Краткая ручная запись `0x31780000` с возвратом `0x39780000` сопровождалась
неуверенным наблюдением, что один вентилятор замедлился; второй не запустился.
Это **не** подтверждает соответствие 0 = быстро, 1 = медленно.

Обрезанная команда `reg flashget 0x1` повесила старую консоль. Длинная вставка
могла терять байты; переполнение аппаратного FIFO — гипотеза, не установленная
причина. Новая сборка даёт короткие команды и проверку аргументов `reg`.
Новые измерения платы не являются условием запрошенного программного теста.

## Команды после установки этого BIN

Вводить по одной строке в `RTK#`, не копируя приглашение:

| Команда | Действие |
| --- | --- |
| `cool status` | Версия сборки, GPIO control/direction/data, уровни GPIO26/27, state, ticks и сумма PoE |
| `cool test 0` | Удержать GPIO27 в 0 до 100 raw-тиков, затем вернуть штатный контроллер |
| `cool test 1` | Такой же тест для уровня 1 |
| `cool auto` | Прервать тест и пересчитать штатный выход по текущей нагрузке PoE |

Сначала `cool status`, затем один уровень: наблюдать оба вентилятора и FAN,
после чего снова посмотреть статус. Перед другим тестом дождаться `mode=auto`.
`cool auto` отменяет тест раньше. Команда включена в `help` и `help cool`.
Повтор `cool` пустой строкой отключён. В прежней v0.1.1 этих команд нет.

Лимит — **100 raw-тиков IRQ**, а не проверенное число секунд. Возврат обслуживают
опрос UART даже без ввода и штатный путь PoE/контроллера. При остановке таймера
или блокировке CPU/главного цикла возврат может задержаться: это программный
тайм-аут, не независимый аппаратный watchdog. Если возврат не подтверждается,
выполнить `cool auto`; при зависшей консоли выключить и включить питание,
не оставляя неизвестный режим теста. В flash тест не сохраняется.

Меняется только бит данных GPIO27 через штатное read/modify/write. Здесь нет
выбора отдельного вентилятора, произвольного напряжения, частоты PWM, регулировки
RPM, изменения порогов или постоянного стартового разгона. Повторный тест во
время активного отклоняется и не продлевает срок. Неизвестное состояние,
не-GPIO mux или направление не «выход» запрещают начало теста.

## Реализация и состояние таймера

Штатный контроллер `0xbfc5c368` продолжает суммировать PoE. В авто сохранены
пороги: сумма <1460 даёт 1; >=1501 даёт 0; 1460–1500 сохраняет прежнее состояние.
Единица суммы — 0,1 Вт. Уровни намеренно не названы скоростями вентилятора.

Новая постоянная SRAM не выделяется. На время теста штатное слово состояния
`0xbf014840` содержит `0xd4000000 | saved_state<<25 | level<<24 | start_tick24`.
Маска метки — `0xfc000000`; штатные значения остаются 0/1. Ветка неизвестного
состояния старого контроллера сохраняет метку, продолжая обновлять сумму PoE.
Перехваченный выход удерживает уровень. При истечении/отмене восстанавливается
сохранённое состояние и вызывается штатный контроллер: он оценивает **текущую**
нагрузку перед записью. Разность тиков считается по модулю 24 бит; переходы
через границы 24 и 32 бит проверены.

Исходный образ закреплён SHA-256. Помимо прежних JSON/UART hooks заменены вход
функции GPIO27, два вызова поиска CLI-команд и вызов опроса UART. Код помещается
в проверенное FF-заполнение; линкер запрещает writable globals, BSS и GOT/PLT.
См. [manifest](../releases/v0.1.2-cooling/build-manifest.json).

## JSON и ограничения защиты reg

`GET /stats.json` сохраняет штатную авторизацию и добавляет необязательный блок
`cooling` в схему версии 1. Ответы v0.1.1 проходят обновлённую схему; клиентам
со старой строгой схемой нужно обновить её для нового блока. HTTP только читает:
он не отменяет тест, не обслуживает его истечение и не меняет GPIO.
[Справочник полей `cooling`](JSON-API.ru.md#cooling-v012).

`fan_rpm` и `fan_status` остаются null. GPIO26 — выборка входа, который код
использует для LED; это не подтверждённый тахометр или здоровье отдельного
вентилятора. Регистры читаются последовательно, аппаратно атомарного снимка нет.

Обёртка `reg` проверяет число аргументов, полностью корректное беззнаковое число,
переполнение 32 бит, выравнивание на 4 байта и границы адреса/количества.
Смещения `soc*`, `9300*` и ASIC ограничены 16 битами. `flashget/flashset` вопреки
названию обращаются к SRAM: здесь разрешены смещения 0..`0x1fffc`, а `flashget`
ограничен 64 словами (0 в штатной команде означает одно слово). Во время теста
записи через `reg` запрещены. Другие штатные команды от этого не становятся
командами только для чтения.

Проверка не обнаружит потерю цифры, если остаток — допустимый выровненный адрес,
и не делает любое корректное обращение к регистру безвредным. Например,
обрезанное `0x350` синтаксически допустимо. Для этого теста использовать `cool`.

## Проверки и следующий аппаратный шаг

Пройдены 24 MIPS-теста: 10 cooling/CLI, 10 HTTP/JSON, 4 scheduler/boot. Проверены
оба уровня, границы гистерезиса, переполнение таймера, возврат без ввода, отмена,
сохранение прочих GPIO, неполный `reg`, авторизация и отсутствие записей при
чтении JSON, принятие/отклонение CRC и общая RAM UART/HTTP. Host serializer/MIB
и ASan/UBSan пройдены; LeakSanitizer отключён из-за ptrace в среде исполнения.
[Отчёты](../releases/v0.1.2-cooling/README.ru.md).

Позднее владелец подтвердил активный тест: data `0x31780000`, GPIO27=0,
осталось 100 тиков; отдельный вывод режима auto показал `0x39780000`.
Явного эффекта на вентиляторы или подтверждённого старта второго нет. Это не
устанавливает соответствие уровней напряжению/скорости. Не повторять то же
чтение как невыполненное условие. Для отдельных RPM нужны подтверждённый
таховход и временная база. [Анализ кода и возможности GPIO26](../research/COOLING-PATHS.ru.md).
